# Аудит проекта ToDoro

Проведи полный аудит проекта ToDoro (Python, SQLite, Kotlin). Сначала ничего не меняй — только
анализ и отчёт с приоритетами (критично / важно / желательно), для каждой проблемы: файл и
строка, почему это проблема, как исправить.

Если пользователь передал аргументы (например, `/audit python` или `/audit android`) —
проверь только эту часть.

## Пути и инструменты

- Проект: `D:\Claude\ToDoro`. Python: `%LOCALAPPDATA%\Python\bin\python.exe`.
- Инструменты проверки ставь только с согласия пользователя (`python -m pip install --user ...`).
  Если чего-то нет — скажи, что именно, и предложи установить; не устанавливай молча.
- bandit на Python 3.15 не ставится (нет готового PyYAML) — вместо него `ruff check . --select S`
  (те же проверки). pip-audit, mypy, pytest, pytest-cov установлены (18.10.2026). Файл
  `.coverage` после `pytest --cov` удаляй — он не для git.
- Android lint: `gradlew lintRelease` (~6 мин) → `android/app/build/reports/lint-results-release.txt`.
- Android: JDK и Gradle — в `D:\Claude\android-tools` (как в `tools/build_apk.py`:
  `JAVA_HOME` = последняя папка `jdk-*`, `GRADLE_USER_HOME` = `gradle-home`), запуск
  `android\gradlew.bat` из папки `android`. Долгие сборки — в фоне.
- Ничего не запускай на настоящих данных пользователя в `%APPDATA%\ToDoro`: для
  `EXPLAIN QUERY PLAN` создай базу во временной папке (scratchpad) через `db.connect()` и
  заполни примерами (`examples.py`).
- Отчёт пиши по-русски, простыми словами: пользователь — не программист. Термины поясняй.

## PYTHON

- Запусти и разбери результаты: `bandit -r .` (безопасность), `pip-audit` (уязвимости
  зависимостей), `ruff check .` (качество кода), `mypy` (типы), `pytest --cov` (покрытие
  тестами). Если чего-то нет — предложи установить.
- Проверь: секреты и ключи в коде, валидацию входных данных, авторизацию и доступ к чужим
  задачам, хеширование паролей, обработку ошибок (не утекают ли трейсбеки наружу),
  небезопасные eval/pickle/subprocess.

## SQLITE

- Все запросы только параметризованные (никаких f-строк и конкатенации в SQL).
- Найди N+1 запросы, запросы в циклах, `SELECT *`.
- Для основных запросов выполни `EXPLAIN QUERY PLAN` и предложи недостающие индексы.
- Проверь использование транзакций при массовых вставках/обновлениях, режим WAL,
  `PRAGMA foreign_keys = ON`, корректное закрытие соединений, миграции схемы.
- Учитывай особенности общих списков в сетевой папке (см. CLAUDE.md): там нельзя
  `journal_mode=PERSIST/TRUNCATE`, а WAL по сети SMB не работает — не советуй то, что
  сломает общие списки.

## KOTLIN / ANDROID

- Запусти и разбери: `./gradlew lint`, detekt, ktlint (если подключены — если нет,
  предложи подключить).
- Проверь: обращения к БД и сети не в главном потоке, корректность корутин и scope (утечки,
  отмена), утечки Activity/Context, хранение токенов (должно быть через
  Keystore/EncryptedSharedPreferences, не в обычных SharedPreferences), HTTPS и
  network_security_config, exported-компоненты в AndroidManifest, логирование
  чувствительных данных, включён ли R8/ProGuard в release.
- Если используется Room — проверь запросы, индексы в `@Entity`, использование Flow, миграции.
- Проверь устаревшие зависимости в Gradle.

## ОБЩЕЕ

- Дублирование и мёртвый код, слишком сложные функции, согласованность API между клиентом
  (`Api.kt`, `Repo.kt`) и сервером (`phone.py`).

## После отчёта

Жди подтверждения пользователя, прежде чем вносить изменения. Когда пользователь разрешит
исправления — после каждого изменения прогоняй `python -m unittest discover tests`,
делай коммит с русским сообщением и `git push`, а заметные пользователю правки записывай
в `RELEASE_NOTES.md` под `## Не выпущено`.
