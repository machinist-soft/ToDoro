# Выпуск новой версии ToDoro

Выполняй шаги по порядку. Пользователь — начинающий, пишет по-русски: в конце коротко и
простыми словами расскажи, что сделано, со ссылкой на выпуск. Если какой-то шаг не удался —
остановись, объясни, что случилось, и не публикуй выпуск.

## Пути и инструменты

- Проект: `D:\Claude\ToDoro`, ветка `main`, GitHub: `machinist-soft/ToDoro` (публичный).
- Python: `%LOCALAPPDATA%\Python\bin\python.exe`
- git: `C:\Program Files\Git\cmd\git.exe` (в PowerShell может не быть в PATH — обнови `$env:Path`
  из переменных Machine + User).
- gh: `%LOCALAPPDATA%\Programs\GitHub CLI\bin\gh.exe` (пользователь входит сам: `gh auth login --web`).
- Если git/curl ругается на `CRYPT_E_NO_REVOCATION_CHECK` — `-c http.schannelCheckRevoke=false` / `--ssl-no-revoke`.
- Длинные Python-правки удобнее писать в файл в scratchpad и запускать, а не heredoc в Bash.

## 1. Проверка перед выпуском

1. `git status` — всё закоммичено и отправлено (`git push`). Если есть незакоммиченные
   изменения — спроси пользователя, входят ли они в выпуск.
2. Автотесты: `python -m unittest discover tests` — должны пройти.
3. В `RELEASE_NOTES.md` есть раздел `## Не выпущено` с записями. Если его нет или он пуст —
   посмотри `git log` с прошлого выпуска (тег `vX.Y`) и спроси пользователя, что выпускать.
4. Коротко покажи пользователю план выпуска: «Планирую выпустить версию X.Y: …» — номер
   версии, что в неё входит (по `## Не выпущено`), будет ли новая версия Android-приложения
   (правила — в разделах 2 и 6а). Жди подтверждения. Дальше остановок нет: после «да» иди
   по шагам до конца без
   новых вопросов (кроме случаев, когда шаг не удался или план приходится заметно менять).

## 2. Номер версии

- Текущий — `APP_VERSION` в `todoro.py` (установщик берёт его оттуда).
- Новые возможности → следующая «малая» версия (`2.3` → `2.4`); только исправления →
  «заплатка» (`2.3` → `2.3.1`). Номер назови пользователю в плане и в отчёте.
- Поменяй `APP_VERSION = "..."` в `todoro.py`.
- В `.github/ISSUE_TEMPLATE/bug_report.yml` и `feature_request.yml` обнови `placeholder` поля
  «Версия ToDoro» на новый номер.

## 3. RELEASE_NOTES.md

- `## Не выпущено` → `## <версия> — <ДД.ММ.ГГГГ>` (сегодняшняя дата). Новые записи — сверху.
- Приведи раздел в порядок для пользователей: подзаголовки `### Новое`, `### Улучшения`,
  `### Исправления` (только непустые; если пунктов мало — можно без подзаголовков).
- Убери внутреннюю кухню: «раньше было белым» про функцию, которой ещё не было в выпусках,
  объединяй правки одной новой функции в один пункт. Пиши простым языком, как пользоваться
  (путь в меню: «☰ Меню → Настройки → …»).
- Только пункты одного уровня — **без вложенных списков** (`  - ...`): окно обновления в
  программе склеивает их в одну строку с чёрточками. Вместо вложенности — отдельные пункты.

## 4. README.md и справка

- `README.md`: раздел «Возможности / Features» (русский список и английский абзац курсивом)
  должен перечислять все крупные возможности выпуска. Для новой заметной функции — свой
  раздел `### Название / English` с одной строкой по-русски, одной по-английски и скриншотом
  `docs/screenshots/<имя>.png`. Первая строка README (описание программы) — актуальна?
- `help_text.py` (справка F1): у каждой новой функции есть раздел или пункты, в
  «Окно программы»/«Настройки» и горячих клавишах нет устаревших описаний. Проверь поиском
  по ключевым словам новой функции.
- Ознакомительный тур (`tour_steps()` в `todoro.py`): новая заметная функция должна быть
  упомянута в подходящем шаге (или в отдельном шаге, если она — новая часть окна), описания
  шагов не должны устареть. Длинный текст проверь снимком шага — подсказка не обрезана
  (снимать на временных данных, как в `tools/make_screenshots.py`, шаг 5в).
- Описание репозитория на GitHub (`gh repo view machinist-soft/ToDoro --json description`)
  совпадает с первой строкой README; если README поменялся — `gh repo edit --description "..."`.

## 5. Скриншоты

1. Если появилась новая заметная функция без скриншота — добавь съёмку в
   `tools/make_screenshots.py` (по образцу шагов в `run()`; при желании — отдельный режим
   запуска, как `dark` / `matrix`).
2. Сними всё заново (окно встанет поверх остальных на ~20 с, мышь лучше не трогать —
   предупреди пользователя одной фразой):
   - `python tools/make_screenshots.py` — светлая тема, все снимки и `catbus.gif`;
   - `python tools/make_screenshots.py dark` — `dark.png`.
   Снимок окна обновления (`update.png`) берёт последний выпущенный раздел RELEASE_NOTES —
   поэтому снимать ПОСЛЕ шага 3.
3. Посмотри (Read) хотя бы `list.png`, `update.png`, `dark.png` и снимок новой функции:
   нет ли пустых/обрезанных окон, чужих окон в кадре. «screen grab failed» — компьютер
   заблокирован: скажи пользователю, не жди.

## 6. Установщик

- `python tools/build_installer.py` (несколько минут, вывод — в лог в scratchpad) →
  `dist\ToDoro-Setup-<версия>.exe`.
- Установщик на этом компьютере НЕ запускай с настоящим `%APPDATA%` (заменит ярлык
  разработки на рабочем столе). Если нужна проверка — только с `APPDATA`, направленным в scratchpad.

## 6а. Приложение для Android

- Если с прошлого выпуска менялась папка `android/` (`git diff --stat v<прошлая версия> -- android`),
  подними в `android/app/build.gradle.kts` `versionCode` на 1 и `versionName` (иначе телефон не
  поставит новый APK поверх старого).
- `python tools/build_apk.py` → `dist\ToDoro-<versionName>.apk` (нужен ключ подписи
  `D:\Claude\android-tools\keys` — без него APK подпишется отладочным ключом и не встанет поверх
  установленного; тогда остановись и скажи пользователю).
- Скопируй его в `dist\ToDoro.apk`: **имя без версии обязательно** — QR-код «Установить
  приложение» в окне «Подключить телефон» ведёт на `releases/latest/download/ToDoro.apk`.
- APK прикладывается к **каждому** выпуску (даже если Android не менялся), иначе ссылка
  из QR-кода сломается.

## 7. Коммит

- `git add` изменённые файлы (todoro.py, RELEASE_NOTES.md, README.md, help_text.py,
  .github/ISSUE_TEMPLATE/*, docs/screenshots/*, tools/*) — никогда не добавляй `*.db`,
  `*.lnk`, `build/`, `dist/`.
- Сообщение: `Версия <версия>` (+ строка Co-Authored-By по правилам сессии), `git push`.

## 8. GitHub Release

1. Текст выпуска = раздел версии из RELEASE_NOTES.md (без строки `## ...`), затем
   разделитель и скриншоты. **Разделитель `---` обязателен**: окно обновления в программе
   показывает текст только до него, ссылки на картинки туда попасть не должны.
   ```
   <раздел версии>

   ---

   ### Как это выглядит

   <подпись>:

   ![<подпись>](https://raw.githubusercontent.com/machinist-soft/ToDoro/<полный SHA коммита>/docs/screenshots/<файл>.png)
   ```
   Ссылки — на полный SHA коммита из шага 7 (не на `main`), чтобы картинки выпуска не
   менялись потом. Показывай снимки новых функций выпуска + `list.png` / `board.png` /
   `dark.png` по смыслу. Проверь, что каждая ссылка отдаёт 200 (`curl -s -o /dev/null -w "%{http_code}"`).
2. `gh release create v<версия> dist/ToDoro-Setup-<версия>.exe dist/ToDoro.apk --title "ToDoro <версия>" --notes-file <файл> --target main`
3. Проверки:
   - `gh release view v<версия> --json assets,isDraft` — установщик и `ToDoro.apk` приложены, не черновик;
   - `curl -s --ssl-no-revoke -o /dev/null -w "%{http_code}" -L https://github.com/machinist-soft/ToDoro/releases/latest/download/ToDoro.apk`
     → 200 (по этой ссылке телефон скачивает приложение из QR-кода);
   - `curl -s --ssl-no-revoke https://api.github.com/repos/machinist-soft/ToDoro/releases/latest`
     → `tag_name` = новая версия;
   - так видит выпуск программа: `python -c "import updater, re; r = updater.fetch_latest(); print(r['version']); print(re.sub(r'^#+\s*', '', r['notes'], flags=re.M).split('\n---', 1)[0][-300:])"`
     — версия новая, текст заканчивается последним пунктом изменений, без ссылок на картинки.

## 9. После выпуска

- Перезапусти программу пользователя: закрой окно ToDoro мягко (`CloseMainWindow` у процесса
  `pythonw` с заголовком `*ToDoro*` — когда активна справка, заголовок «Справка — ToDoro») и
  запусти ярлык `%USERPROFILE%\Desktop\ToDoro.lnk`. Проверь, что осталась одна копия программы.
- Отчёт пользователю: номер версии, ссылка
  `https://github.com/machinist-soft/ToDoro/releases/tag/v<версия>`, что вошло (2–5 пунктов),
  что обновлено (README, справка, скриншоты), что не удалось проверить — прямо.
